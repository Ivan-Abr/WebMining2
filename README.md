# Описание процессов программы извлечения и анализа научных статей

**Тема ВКР:** Создание интеллектуального агента для автоматизации DevOps-процессов на основе генерации и выполнения скриптов с помощью LLM

---

## Общая архитектура

Программа реализована в виде последовательного конвейера (pipeline), состоящего из пяти независимых шагов. Каждый шаг сохраняет результат в файл, поэтому любой из них можно запустить отдельно, не повторяя предыдущие.

```
Шаг 1: Сбор данных        →  data/raw/*.json
Шаг 2: Препроцессинг      →  data/processed/*.json + *.npz + *.joblib
Шаг 3: Классификация      →  data/results/confusion_matrix_*.png + models_comparison.csv
Шаг 4: Кластеризация      →  data/results/elbow_curve.png + clusters_tsne.*
Шаг 5: Итоговый отчёт     →  data/results/articles_final.csv
```

Запуск полного конвейера:

```bash
python main.py --all
```

## Шаг 1. Сбор данных (`collect/`)

### 1.1 Источники

Данные собираются из двух источников одновременно:

| Источник | Модуль | Метод доступа |
|---|---|---|
| arXiv | `arxiv_client.py` | HTTP-запросы к `arxiv.org/search/` + парсинг HTML через BeautifulSoup |
| Semantic Scholar | `semantic_scholar.py` | REST API `api.semanticscholar.org/graph/v1/paper/search` |

### 1.2 Поисковые запросы

Оба источника опрашиваются по одному и тому же списку из 10 запросов, подобранных под тему ВКР:

```
"LLM DevOps automation agent"
"large language model script generation"
"intelligent agent CI/CD pipeline"
"GPT code generation DevOps"
"AI automation infrastructure scripts"
"LLM software engineering automation"
"natural language DevOps pipeline"
"code generation continuous integration"
"GitLab automation AI agent"
"LLM bash python script generation"
```

### 1.3 Процесс сбора с arXiv (`arxiv_client.py`)

Модуль выполняет постраничный обход результатов поиска:

1. Формирует GET-запрос к `https://arxiv.org/search/` с параметрами `searchtype=all`, `query` и `start` (смещение страницы).
2. Получает HTML-страницу с результатами (до 25 статей на страницу).
3. Парсит HTML через `BeautifulSoup`: ищет элементы `<li class="arxiv-result">`, из каждого извлекает:
   - `<p class="title">` — заголовок
   - `<span class="abstract-full">` или `<p class="abstract">` — аннотацию
   - `<p class="authors">` — список авторов (строка, затем разбивается по запятой)
   - `<p class="list-title"><a href=...>` — URL статьи (вида `/abs/2401.xxxxx`)
   - из URL автоматически строится ссылка на PDF: `/abs/` → `/pdf/`
4. Повторяет шаги 1–3, увеличивая `start` на 25, пока не наберёт `max_results` статей или не получит пустую страницу.
5. Между запросами делает паузу **3 секунды** во избежание блокировки (rate limiting).
6. Каждая статья сохраняется как словарь с полями: `title`, `abstract`, `authors` (список), `year`, `url`, `pdf`, `source="arxiv"`.

Максимум: **50 статей на запрос**, итого до ~500 с arXiv.

### 1.4 Процесс сбора с Semantic Scholar (`semantic_scholar.py`)

1. Формирует GET-запрос к `https://api.semanticscholar.org/graph/v1/paper/search` с параметрами `query`, `fields=title,abstract,authors,year,externalIds,openAccessPdf` и `limit=100`.
2. API возвращает JSON с массивом `data` — список статей.
3. Из каждой статьи извлекается:
   - `title`, `abstract`, `year` — напрямую из JSON
   - `authors` — список словарей `[{"name": "..."}]`, преобразуется в список строк
   - `url` — берётся из поля `openAccessPdf.url`, если есть open-access PDF; иначе формируется как `https://www.semanticscholar.org/paper/{paperId}`
4. При получении HTTP 429 (rate limit) модуль читает заголовок `Retry-After` и ждёт указанное количество секунд перед повтором.
5. Пагинация: если API вернул меньше статей чем запрошено, считается что результаты исчерпаны.
6. Между запросами — пауза **1.5 секунды**.

Максимум: **100 статей на запрос**, итого до ~1000 с Semantic Scholar.

### 1.5 Результат сбора

После обхода всех запросов по каждому источнику данные сохраняются:

```
data/raw/arxiv.json             — статьи с arXiv
data/raw/semantic_scholar.json  — статьи с Semantic Scholar
```

Формат каждой записи в JSON:

```json
{
  "title":    "LLM-based Intelligent Agent for DevOps Automation",
  "abstract": "In this paper we propose...",
  "authors":  ["Alice Smith", "Bob Jones"],
  "year":     2024,
  "url":      "https://arxiv.org/abs/2401.12345",
  "source":   "arxiv"
}
```

## Шаг 2. Препроцессинг (`preprocess/`)

Препроцессинг состоит из трёх последовательных операций: очистка текста → разметка → векторизация.

### 2.1 Загрузка и дедупликация (`cleaner.py`)

1. Оба JSON-файла из `data/raw/` загружаются и объединяются в один список.
2. **Дедупликация** по заголовку: для каждой статьи вычисляется нормализованный ключ — заголовок приводится к нижнему регистру и сжимаются лишние пробелы. Если такой ключ уже встречался, статья отбрасывается. При этом статья из arXiv имеет приоритет перед Semantic Scholar, так как arXiv загружается первым.

### 2.2 Очистка текста (`clean_text`)

Для каждой статьи поля `title` и `abstract` объединяются в одну строку и проходят через следующую цепочку:

**Шаг 1 — Нижний регистр.**
Весь текст приводится к нижнему регистру. Это устраняет различие между `"DevOps"` и `"devops"` при последующей токенизации.

**Шаг 2 — Удаление LaTeX-разметки.**
Удаляются математические формулы вида `$x = y^2$` и команды LaTeX вида `\mathbf{W}`. Такие конструкции часто встречаются в научных статьях и не несут семантической нагрузки для классификатора.
Регулярное выражение: `\$[^$]*\$|\\\w+\{[^}]*\}`

**Шаг 3 — Удаление спецсимволов.**
Из текста удаляются все символы кроме латинских букв и пробелов: цифры, знаки препинания, дефисы, скобки. Это предотвращает появление бессмысленных токенов вроде `"2024,"` или `"(gpt-4)"`.
Регулярное выражение: `[^a-z\s]`

**Шаг 4 — Нормализация пробелов.**
Все последовательности пробельных символов (пробел, табуляция, перенос строки) заменяются одним пробелом.

**Шаг 5 — Удаление стоп-слов.**
Из токенов убираются 318 английских стоп-слов из встроенного списка `sklearn.feature_extraction.text.ENGLISH_STOP_WORDS`: `the`, `is`, `in`, `of`, `and`, `for`, `with`, `this`, `are`, и т.д. Эти слова встречаются почти в каждом тексте и не помогают различать категории.

**Шаг 6 — Лемматизация.**
К каждому токену применяется упрощённая лемматизация по суффиксным правилам:
- `automation` → `automat` (суффикс `-tion`)
- `generating` → `generat` (суффикс `-ing`, длина > 6)
- `automated` → `automat` (суффикс `-ed`, длина > 5)
- `usefulness` → `useful` (суффикс `-ness`)
- `deployment` → `deploy` (суффикс `-ment`)

Токены короче 3 символов отбрасываются.

**Пример преобразования:**

```
Исходный текст:
"Automated Script Generation for CI/CD Pipelines using LLM Agents"

После очистки:
"automat script generat cicd pipelin llm agent"
```

Статьи, в которых после очистки осталось меньше 20 токенов, отбрасываются как нерелевантные.

Результат сохраняется в `data/processed/articles_cleaned.json`.

### 2.3 Авто-разметка (`labeler.py`)

Поскольку у нас нет вручную размеченного датасета, каждой статье присваивается метка автоматически по ключевым словам. Это стандартный подход для слабо-размеченных текстовых корпусов (weak supervision).

**Пять категорий и их ключевые слова:**

| Метка | Описание | Примеры ключевых слов |
|---|---|---|
| `llm_agents` | LLM-агенты и автономные системы | `llm agent`, `autonomous agent`, `gpt agent`, `copilot` |
| `script_generation` | Генерация кода и скриптов | `script generation`, `code synthesis`, `bash generation`, `iac generation` |
| `devops_automation` | Автоматизация DevOps и инфраструктуры | `devops automation`, `mlops`, `gitops`, `site reliability` |
| `cicd_ai` | CI/CD с применением ИИ | `ci/cd`, `continuous integration`, `gitlab`, `github actions` |
| `testing_automation` | Автоматическое тестирование | `test automation`, `unit test generation`, `regression testing` |

**Алгоритм присвоения метки:**

1. Берётся исходный текст статьи (до очистки) — `title + abstract` в нижнем регистре. Используется именно исходный текст, а не очищенный, так как многословные ключевые фразы вроде `"ci/cd"` или `"llm agent"` могут быть искажены при удалении спецсимволов.
2. Для каждой из 5 категорий подсчитывается количество совпадений её ключевых слов в тексте.
3. Статье присваивается метка той категории, у которой наибольший счёт.
4. При одинаковом счёте у нескольких категорий выбирается первая в алфавитном порядке.
5. Если ни одно ключевое слово не совпало — метка `"other"`.

Статьи с метками, встречающимися реже **5 раз**, исключаются из выборки — это минимум для корректного стратифицированного разбиения на train/test.

Результат сохраняется в `data/processed/articles_labeled.json`.

### 2.4 TF-IDF векторизация (`vectorizer.py`)

Классификаторам нужны числовые векторы, а не строки. Для преобразования текстов используется метод **TF-IDF** (Term Frequency — Inverse Document Frequency).

**Что такое TF-IDF:**
Для каждого слова в каждой статье вычисляется вес:

```
TF(t, d)  = log(1 + количество вхождений слова t в статье d)   # sublinear_tf=True
IDF(t)    = log(N / df(t))  — N — общее число статей, df(t) — сколько статей содержат t
TF-IDF(t, d) = TF(t, d) × IDF(t)
```

Слова, встречающиеся почти в каждой статье (например, `"paper"`, `"approach"`), получают низкий IDF и малый вес. Редкие, но характерные слова (`"terraform"`, `"copilot"`) получают высокий вес.

**Параметры векторайзера:**

| Параметр | Значение | Объяснение |
|---|---|---|
| `max_features` | 5000 | Оставляем только 5000 наиболее информативных слов/н-грамм |
| `ngram_range` | (1, 2) | Учитываются как одиночные слова, так и биграммы (`"code generation"`, `"llm agent"`) |
| `min_df` | 2 | Признак включается только если встречается хотя бы в 2 статьях |
| `sublinear_tf` | True | Применяем логарифм к TF для сглаживания частоты |
| `strip_accents` | unicode | Нормализуем диакритические знаки |

**Результат:** разреженная матрица размером `N × 5000`, где N — количество статей. Большинство ячеек равны нулю (статья не содержит большинство слов из словаря), поэтому матрица хранится в формате `scipy.sparse` для экономии памяти.

Сохраняемые артефакты:
```
data/processed/tfidf_matrix.npz       — разреженная матрица (scipy sparse)
data/processed/tfidf_vectorizer.joblib — обученный векторайзер
data/processed/labels.json            — список меток в том же порядке, что строки матрицы
```

## Шаг 3. Классификация (`classify/`)

### 3.1 Разбивка на выборки

Перед обучением данные делятся на обучающую и тестовую выборки:
- **80% — обучение** (train), **20% — тест** (test)
- Разбивка **стратифицированная**: в каждой части сохраняется то же соотношение классов, что и в полной выборке. Это важно при несбалансированных данных.
- Фиксированный `random_state=42` обеспечивает воспроизводимость разбивки.

Метки переводятся из строк в числа через `LabelEncoder` из sklearn: `cicd_ai → 0`, `devops_automation → 1`, и т.д.

---

### 3.2 Основной классификатор: Gradient Boosting (`gradient_boosting.py`)

Используется `HistGradientBoostingClassifier` из sklearn — оптимизированная версия градиентного бустинга с гистограммным разбиением.

**Принцип работы Gradient Boosting:**

Метод строит ансамбль деревьев решений последовательно. Каждое следующее дерево обучается на **ошибках** предыдущих:

1. Начинаем с наивной модели (предсказание — среднее значение по всем примерам).
2. Вычисляем **остатки** (разницу между предсказаниями и реальными метками).
3. Строим новое дерево, которое предсказывает эти остатки.
4. Обновляем итоговую модель: добавляем предсказание нового дерева с весом `learning_rate`.
5. Повторяем шаги 2–4 ещё `n_estimators - 1` раз.

Итоговое предсказание — взвешенная сумма предсказаний всех деревьев.

**HistGradientBoosting** отличается от классического GBT тем, что непрерывные признаки разбиваются на гистограммные корзины (bins) перед построением каждого дерева. Это ускоряет обучение на больших выборках и лучше работает с матрицей TF-IDF.

**Параметры модели:**

| Параметр | Значение | Роль |
|---|---|---|
| `max_iter` | 200 | Количество деревьев в ансамбле |
| `max_depth` | 4 | Максимальная глубина каждого дерева |
| `learning_rate` | 0.1 | Вклад каждого нового дерева (шаг обновления) |
| `random_state` | 42 | Фиксация случайности |

**Важный нюанс:** `HistGradientBoostingClassifier` не принимает разреженные матрицы (`scipy.sparse`) напрямую. Поэтому перед обучением и предсказанием вызывается `.toarray()` — преобразование в плотную матрицу NumPy.

---

### 3.3 Базовый классификатор: Naive Bayes (`naive_bayes.py`)

Используется `MultinomialNB` — наивный байесовский классификатор для дискретных (счётных) признаков. Это стандартный baseline для задач классификации текстов.

**Принцип работы:**

По теореме Байеса вероятность того, что документ `d` принадлежит классу `c`:

```
P(c | d) ∝ P(c) × ∏ P(t | c)^(TF-IDF(t, d))
```

- `P(c)` — априорная вероятность класса (доля статей данной категории в обучающей выборке)
- `P(t | c)` — вероятность встретить слово `t` в документах класса `c`
- `α = 0.1` — сглаживание Лапласа (аддитивное сглаживание для редких слов)

Классификатор называется «наивным», потому что предполагает **независимость** всех признаков (слов) друг от друга, что в реальности неверно, но на практике работает хорошо для текстов.

**Преимущество перед Gradient Boosting:** обучается мгновенно и напрямую принимает разреженную матрицу без конвертации в dense.

### 3.4 Оценка качества (`evaluator.py`)

Для каждого классификатора вычисляются три метрики на тестовой выборке:

**Accuracy (точность):**
Доля правильно классифицированных статей от общего числа.
```
Accuracy = (TP + TN) / (TP + TN + FP + FN)
```
Может вводить в заблуждение при несбалансированных классах (например, если 80% статей относятся к одному классу, классификатор может просто всегда предсказывать его).

**Macro F1:**
Среднее значение F1-меры по всем классам, где каждый класс имеет **одинаковый вес**. Штрафует за плохую работу с малочисленными классами.
```
F1(c) = 2 × Precision(c) × Recall(c) / (Precision(c) + Recall(c))
Macro F1 = среднее F1(c) по всем c
```

**Weighted F1:**
Среднее значение F1-меры, взвешенное по **числу примеров** в каждом классе. Более объективен при несбалансированных данных.

Дополнительно строится **матрица ошибок (Confusion Matrix)** — таблица, где строки соответствуют истинным меткам, а столбцы — предсказанным. Диагональ — правильные предсказания, остальные ячейки — ошибки. Визуализируется в виде heatmap и сохраняется в PNG.

**Сравнительная таблица** обеих моделей сохраняется в `data/results/models_comparison.csv`.

После обучения модели модуль дополнительно выполняет предсказания для **всех** статей набора данных (не только тестовой выборки) — чтобы записать поле `predicted_label` в каждую запись для итогового отчёта.

Сохраняемые файлы:
```

data/results/nb_classifier.joblib           — модель Naive Bayes
data/results/label_encoder.joblib           — кодировщик меток
data/results/confusion_matrix_gradientboosting.png
data/results/confusion_matrix_naivebayes.png

```

## Шаг 4. Кластеризация (`cluster/`)

Кластеризация выполняется независимо от классификации: метки классов здесь не используются. Алгоритм сам находит группы похожих статей.

### 4.1 Выбор числа кластеров: метод Elbow (`kmeans.py`)

Алгоритм K-means требует заранее указать число кластеров `k`. Для автоматического выбора используется **метод локтя (Elbow method)**:

1. K-means запускается для каждого значения k от 2 до 10.
2. Для каждого k записывается **инерция** (SSE — Sum of Squared Errors): сумма квадратов расстояний от каждой точки до центра её кластера.
3. Строится график зависимости инерции от k. При малых k инерция резко падает; после некоторого значения снижение замедляется — это и есть «локоть».
4. Оптимальное k определяется геометрически: находится точка на кривой, наиболее удалённая от прямой, соединяющей первую и последнюю точки графика (метод максимального перпендикулярного расстояния).

```python
# Вектор направления прямой (k_min, inertia_max) → (k_max, inertia_min)
d = (coords[-1] - coords[0]) / norm(coords[-1] - coords[0])
# Перпендикулярное расстояние каждой точки от прямой
perp_dists = |cross(coords - coords[0], d)|
optimal_k = k_values[argmax(perp_dists)]
```

График сохраняется в `data/results/elbow_curve.png`.

### 4.2 Алгоритм K-means (`run_kmeans`)

K-means итеративно разбивает статьи на k групп, минимизируя внутрикластерное расстояние:

1. **Инициализация:** k центроидов размещаются случайно среди точек данных (n_init=15 — запускается 15 раз с разными начальными условиями, выбирается лучший результат).
2. **Назначение:** каждая статья назначается в кластер с ближайшим центроидом (по евклидову расстоянию в TF-IDF пространстве).
3. **Обновление:** для каждого кластера пересчитывается центроид как среднее всех точек кластера.
4. **Повтор:** шаги 2–3 повторяются до сходимости (пока назначения не перестанут меняться) или до `max_iter=500` итераций.

**Параметры:**

| Параметр | Значение |
|---|---|
| `n_clusters` | k (из метода Elbow) |
| `n_init` | 15 — число перезапусков |
| `max_iter` | 500 — максимум итераций |
| `random_state` | 42 |

### 4.3 Интерпретация кластеров: топ-слова

Чтобы понять, о чём каждый кластер, для каждого из k центроидов (векторов в пространстве TF-IDF) выбираются **10 признаков с наибольшим значением**. Это слова и биграммы, которые наиболее характерны для данного кластера.

```python
for cluster_id, centroid in enumerate(km.cluster_centers_):
    top_indices = centroid.argsort()[::-1][:10]
    top_words[cluster_id] = [feature_names[i] for i in top_indices]
```

Результат сохраняется в `data/results/cluster_top_words.json`. На основе топ-слов можно вручную дать кластерам осмысленные названия в `config.py` в словаре `CLUSTER_NAMES`.

### 4.4 Визуализация: t-SNE (`visualizer.py`)

TF-IDF матрица имеет 5000 измерений — её невозможно визуализировать напрямую. Применяется двухэтапное снижение размерности:

**Этап 1 — TruncatedSVD (50 компонент):**
TruncatedSVD (усечённое сингулярное разложение) — аналог PCA для разреженных матриц. Из 5000 признаков выбираются 50 главных компонент, объясняющих наибольшую часть дисперсии. Это ускоряет последующий t-SNE в сотни раз.

**Этап 2 — t-SNE (2 компоненты):**
t-SNE (t-distributed Stochastic Neighbor Embedding) — нелинейный метод снижения размерности, оптимизированный для визуализации. Он сохраняет локальную структуру: статьи, похожие в исходном пространстве, будут близко расположены на 2D-карте.

Параметры t-SNE:
- `perplexity=30` — баланс между локальной и глобальной структурой
- `learning_rate="auto"` — автоматический шаг градиентного спуска
- `init="pca"` — инициализация из PCA для стабильности
- `max_iter=1000` — число итераций оптимизации

**Результат:**

- `data/results/clusters_tsne.png` — статический scatter plot: каждая точка — статья, цвет — кластер
- `data/results/clusters_tsne.html` — интерактивная версия на Plotly: при наведении на точку показывается заголовок статьи и её метка
